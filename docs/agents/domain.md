# Domain docs

This is a single-context project.

Before domain exploration:

- Read the root `GLOSSARY.md`.
- Read relevant ADRs, including the existing
  `docs/ADR-0001-architecture.md`.
- Read `docs/PRD-jarvis.md` for product requirements.
- New ADRs belong in `docs/adr/`; continue numbering after
  existing ADRs. Create the directory when needed.

Use glossary vocabulary in specifications, code, and tests.
Surface conflicts with ADRs explicitly.
If optional domain documents are absent, continue silently;
create them when terminology or decisions are resolved.
